# 从 Python 版（0.6.5）搬到 Go 版（0.7.0）

这份说明写给已经在用 0.6.5 的人，也写给以后维护的人。要点只有三句：

1. **0.6.5 是 Python 版最后一个版本**，装好可以一直用，不会过期，只是不再加新功能。
2. **0.7.0 换成 Go + Wails 重写**，壳和内核合成一个原生程序；人格、记忆、情绪、自我、模组、存档都会搬过去。
3. **迁移是先读后写**：迁移命令只读旧目录、只写新目录，先 dry-run 列清单，你确认后才动手；旧目录原样留着。

> 写作时（0.6.5 发布）0.7.0 还在开发中，迁移命令的界面和参数以 0.7.0 发布时附带的说明为准。
> 本文把「搬什么、放哪儿、哪些要重做、出问题怎么办」先写清楚，发布时只需要补上具体命令。

---

## 一、两个版本各自把东西放在哪

| 内容 | Python 0.6.5 | Go 0.7.0 |
|---|---|---|
| 程序本体 | 安装目录（默认 `%LOCALAPPDATA%\BetterAIBridge 0.6.5`） | 安装目录（默认 `%LOCALAPPDATA%\Programs\BetterAIBridge`） |
| 人格 / 记忆 / 情绪 / 自我 / 状态 | `<安装目录>\WiseEntity\entity\` | 数据根 `%LOCALAPPDATA%\BetterAIBridgeNext` 下 |
| 模组包（`.pbab`）与启用登记 | `<安装目录>\program_bundle\`（含 `registry.json`） | 数据根下的模组目录 |
| 模组下载的依赖（NapCat、无头内核、微信引擎…） | `<安装目录>\program_cache\` | 数据根下的缓存目录（可以重新下，不必搬） |
| 启动器日志 | `%LOCALAPPDATA%\BetterAIBridge\logs`、`<安装目录>\logs\` | 数据根下 |
| 内核端口与 token | `config\app.yaml`、`WiseEntity\entity\state\core_token` | 新版自己分配，不沿用 |

关键差别：**Python 版把用户数据放在程序目录里，Go 版把它放在单独的“数据根”**。
所以两个版本可以同时装着、互不覆盖；也正因为分开，才需要一次迁移。

---

## 二、会搬过去的东西

迁移命令按下面这份清单搬（`WiseEntity\entity\` 整个树都在内）：

| 目录 / 文件 | 里面是什么 | 搬不搬 |
|---|---|---|
| `entity\persona\persona.md`、`drift.json` | 她是谁：人设、性格底子、漂移记录 | 搬 |
| `entity\memory\` | 会话记忆、关系、证据、摘要 | 搬 |
| `entity\emotion\`、`entity\state\` | 13 维情绪、理智、时间感、状态 | 搬（`core_token` 除外） |
| `entity\self\` | 自我档案、经历、反思、校准记录 | 搬 |
| `entity\brain\`、`entity\registry\` | 大脑缓存、注册表 | 搬（坏了大不了重建） |
| `entity\warehouse\` | 仓库里的图片 / 文档 | 搬 |
| `entity\config\llm.json` | 模型服务商、模型名、**API Key（明文）** | 搬，但建议迁完后换成新 Key |
| `entity\config\{emotion_profile,memory,sense,stomach,tts}.json` | 各项偏好 | 搬 |
| `program_bundle\*.pbab` + `registry.json` | 已导入的模组、启用状态 | 搬（也可在新版里重新导入） |
| `program_cache\` | NapCat、B 站无头内核（约 120 MB）、微信引擎等下载物 | **不搬**，新版第一次用到时重下 |
| `config\app.yaml`、`config\install.json` | 端口、路径、安装身份 | **不搬**，新版自己生成 |

`core_token` 不搬：它是每台机器一份的本机令牌，搬过去没有意义，新版会重新生成。

## 三、账号和登录

- **B 站桥 / QQ 桥的登录态**跟着模组数据走（存在各模组自己的数据里）。迁移会一起搬，
  但 0.6.5 的真机登录本来就没有完整实测过，0.7.0 里**可能需要重新扫码 / 重新登录一次**。
- **模型 API Key** 在 `entity\config\llm.json` 里，迁移会带过去；
  如果你在 0.6.5 里从没填过 Key（向导里跳过不了，所以一般都有），0.7.0 首次启动会再问一次。
- 新版的端口和本机令牌都是新的，旧的 `app.yaml`、`core_token` 不作数；
  自己写的脚本如果直连内核，迁移后要重新取端口和 token。

---

## 四、模组

- **接口不变**：`.pbab` 还是 zip，里面还是 `module.json` / `connection.json` / `settings.schema.json` / `checksum.json`，
  端口还是只读 `BAB_MODULE_PORT`，工具调用还是 `connection.json` 里那套。0.6.5 的五个包（M、pre、routine、B 站、QQ）
  在 0.7.0 里仍然能导入、能启用。
- **版本号规则不变**：模组版本跟着启动器版本走。0.7.0 发布时会同时给一套 `0.7.x` 的配套包；
  手上 0.6.5 的包能用，但以配套包为准（模组契约里 `api: 1` 没变，变的是宿主实现）。
- **模组自己的数据**（比如 QQ 的会话映射、B 站的登录 cookie）在 `program_bundle` / `program_cache` 对应的模组目录里，
  迁移会搬 `program_bundle`，不搬 `program_cache`；重下依赖后如果要求重新登录，按提示来。

## 五、迁移步骤（0.7.0 发布后照这个顺序做）

1. **先留一手**：在 0.6.5 里「设置 → 存档 → 导出」，存一个 `.babpak` 到桌面以外的地方。
   它是兜底，不影响迁移。
2. **正常装 0.7.0**，装到默认的新目录。不要装到 0.6.5 的目录里，也不要让两个版本共用数据目录。
3. **打开 0.7.0 的迁移入口**（设置里的「从 Python 版迁移」，或命令行加 `--dry-run`），先看清单：
   会列出找到的旧安装目录、要搬的目录、文件数、总大小，以及哪些项会被跳过。
4. **确认后执行迁移**。迁移只写新数据根；旧目录一个字节都不改。
5. **验证**：打开 0.7.0，依次看人格（她叫什么、什么脾气）、记忆（最近的对话还在不在）、
   情绪（不是全零）、自我档案（self.md 有内容）、模组（列表里能看见、能启用）。
6. **都正常了再考虑卸 0.6.5**。卸之前再导一次存档；不放心就一直留着，两个版本并存没有副作用。

### 如果迁移失败

- 旧数据不会坏：迁移是「读旧、写新」，失败最多是新目录写了一半。
- 把新数据根删掉重来，或者直接用第 1 步的 `.babpak` 在 0.7.0 里导入。
- 报错信息请连同 `数据根\logs\` 里的日志一起发到 GitHub Issues。

## 六、已知差异（0.7.0 与 0.6.5）

| 项 | 0.6.5（Python） | 0.7.0（Go + Wails） |
|---|---|---|
| 运行环境 | 需要 Python 3.10+ 和三个 venv（壳 / 内核 / 语音） | 单文件程序，不再需要 Python 和 venv |
| 启动方式 | PySide6 壳 + FastAPI 内核两个进程 | 原生窗口 + 内嵌内核 |
| 数据位置 | 安装目录内 | 单独的数据根（默认 `%LOCALAPPDATA%\BetterAIBridgeNext`） |
| 更新方式 | 下载 `update.zip`，独立助手覆盖程序文件 | 单文件替换（以 0.7.0 实际实现为准） |
| 语音 | edge-tts 在线；本地 MOSS 可选包（约 1.3 GB） | edge-tts 在线；本地包需重新下载 |
| 卸载 | 删除程序目录会连 `entity` 一起删 | 程序与数据分开，卸载不影响数据根 |
| 模组 | `.pbab`，契约 `api: 1` | 同一个契约，配套 0.7.x 包 |

界面细节、个别页面（立绘、背景库、插件控制台之类）在两版之间会有出入，以 0.7.0 自己的更新说明为准。

## 七、常见问题

**Q：0.6.5 还能用多久？**
A：能用，没有到期日。它不会再收到新功能，但装好就一直能跑。

**Q：能不能不迁移，直接用 0.7.0 重新养一个？**
A：可以。0.7.0 首次启动就是全新向导，等于重新开始；旧版本还在，随时能回去。

**Q：迁移会不会把 0.6.5 搞坏？**
A：不会。迁移只读旧目录。真要保险，先按第五节第 1 步导一份存档。

**Q：两个版本能同时开吗？**
A：程序上可以并存，但不建议同时运行——它们会各自找端口、各自写自己的数据根，同时开着容易搞混在跟哪个说话。

**Q：模组要不要跟着换？**
A：0.6.5 的包能继续导入；0.7.0 发布时会有一套 0.7.x 配套包，建议换配套包。

**Q：我的 `.babpak` 存档还能导入吗？**
A：能。0.7.0 会保留存档导入；如果格式有调整，迁移命令会先转换再导入。
