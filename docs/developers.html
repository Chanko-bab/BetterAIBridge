模组与参与

一起做模组

不用先成为“开发者”，做出一个能装上的包就可以。

上传自己的模组 管理已有模组
01 · 准备

先做成一个能装上的包

你上传的 .pbab，至少包含：

  • module.json：id、版本、kind、权限
  • introduce.md：模组做什么、改了哪里
  • connection.json：需要哪些桥能力
  • settings.schema.json：设置项
02 · 提交

用 GitHub 发 Release

请把包传到 GitHub Release 的 Assets，不要塞进仓库历史。

然后请开一个「提交模组」Issue，填 Release 链接、署名方式和权限说明。

03 · 审核

维护者会拆包检查

校验包结构、entry、权限和文档；pre 模组还会重点看会写哪些路径。

通过后进模组页。被拒会说明原因，不会悄悄下掉。

04 · 归属

署名归你，责任也归你

模组页会显示你的 GitHub 账号，或「匿名」。

无论是否匿名，提交用的 GitHub 账号都对维护者可见，用于安全、移交和下架。

身份

两种署名，同一套责任

没有独立账号系统。你的 GitHub 账号就是署名身份。

@your-handle 署名发布

公开 GitHub 账号

模组页显示账号和主页链接。读者能顺着账号找到你的其他项目，也能看到你的提交记录。

匿名 匿名发布

不公开账号

模组页只写「匿名」。维护者仍知道是哪个 GitHub 账号提交的，但不会公开。匿名不等于无法追责。

你的权利

你的模组，你说了算

下面这些操作，你都通过「管理已有模组」Issue 发起。维护者只做校验和登记，不替你做决定。

操作谁可以发起怎么走
更新版本 所有者 请你发新 Release，提管理 Issue 选「更新版本」，附版本号和变更。
移交开发权 所有者 + 接手人 请双方都在 Issue 里回复确认；维护者核对后改所有者。旧所有者失去管理权。
下架 所有者 请你提管理 Issue 选「下架」。模组页移除；已安装的副本和他人 fork 不会消失。
切换署名 / 匿名 所有者 请你提管理 Issue 选「改署名」，说明要显示账号还是匿名。
删除 Release 所有者 请你在 GitHub Release 页面自己删；下架和删包是两件事。
匿名不是隐身。 匿名只影响模组页展示；提交 Issue 的 GitHub 账号仍对维护者可见。安全事件、移交争议、冒名投诉都会按这个账号追溯。
审核标准

什么会被拒

  • 包里带可执行文件，但 introduce 没说明
  • 声明只读，实际写文件或改代码
  • pre 模组不说明会改哪些路径
  • 下载器、隐藏更新、捆绑安装
  • 冒用他人账号或项目名
  • 把恶意代码藏进正常功能
  • 权限申请远大于实际用途
  • 文档、版本、checksums 对不上
边界

现在为什么是 Issue，不是控制台

站点是 GitHub Pages 静态页，没有服务器、没有账号数据库，所以不能直接收上传。 现在用 GitHub 账号做身份、Issue 做申请、Release 做分发；维护者人工校验和登记。 等社区真的需要自助面板时，再加后端和 OAuth；那时也不改变「开发者拥有自己的模组」这条规则。

模组是独立程序，不由安装包签名。装之前请先看 introduce 和 connection；请只装你信任的来源。
