# program_routine 设计分析（先分析，暂不动手）

目标：以 M（`program_M.pbab`，v0.1.3）为骨架，做一个「日常事务 + 信息查询」的模组：
提醒/待办/日程/记事/随手存档，外加把旧 `web_bridge` 的网页能力并进来。
本文只做分析与取舍，代码留到下一轮。

---

## 一、它和外界的四张契约

| 契约 | 内容 | 说明 |
|---|---|---|
| `module.json` | `id=routine`、`memory.program=program_routine`、`ports=[40734]`、`bridge.wants=[memory.search, memory.note, notice.push, presence.read]` | 只在真需要时申请 cap：`mood.read`/`brain.snapshot` 暂不申请（本模组不需要知道她的情绪） |
| `connection.json` | 13 个工具 ↔ 13 个端点，一一对齐（0.1.2 加了 `rt_today`） | 名字前缀统一 `rt_`（routine），避免和 M 的 `m_*` 混 |
| `persona.md` | 第一人称讲「我怎么记事、怎么提醒、什么时候该查网」 | 她读这一段 |
| `introduce.md` | 给你的说明书：三类能力的用法、三个设置什么意思、出错看哪里 | 你读全文，她读前 900 字 |

**记忆库是新建的**：抽屉落在 `entity/memory/external/program_routine/<分类>/<天>.txt`，分类由写入决定（提醒 / 待办 / 笔记本 / 日程）。它和 BAB 自己的 `internal/` 完全隔开——她只能通过工具来问，模组也只能写自己的抽屉。

## 二、两条数据（关键取舍）

一条是**给人看的**，一条是**给程序用的**。两者都要，职责不重叠：

1. **结构化库**：`<模组目录>/data/routine.json`
   - `reminders[]`：`{id, text, due_at, recurrence, next_at, done, created_at, fired_at, note}`
   - `todos[]`：`{id, text, done, due_date, priority, created_at, done_at}`
   - `notes[]`：`{id, text, category, tags, created_at}`（账号/地址/尺码/食谱这类"随手存档"）
   - 只存机器要用的字段，原子写（临时文件 + `os.replace`），保留一代 `.bak`。
2. **记忆镜像**：每写入一条，顺手 `memory.note` 一句人话到抽屉（`提醒｜明天 15:00 交水费`）。
   - 好处：她在聊天里"想起来"的时候，靠 `memory.search` 就能捞到；不需要模组常驻被查。
   - 代价：两边可能不一致。规矩是**结构化库为准，镜像只写不读**；对不上时模组自己重整镜像。

> 这一条是本次设计里最需要你确认的取舍：要不要"双写"。我建议双写，因为只存 JSON 她记不住，只存记忆又不能精确到点。

## 三、自然时间怎么解析

不引第三方库（模组只用标准库），自己写一个 `parse_when(text, now)`，只认这些模式，认不出就老实要一次具体时间：

| 类别 | 认这些写法 | 规则 |
|---|---|---|
| 相对 | 3 分钟后 / 半小时后 / 2 小时后 / 3 天后 / 一周后 | 数字 + 分钟/小时/天/周；"半"=0.5 |
| 天 | 今天 / 明天 / 后天 / 大后天 / 今晚 / 明早 | 今晚=今天 20:00，明早=明天 08:00 |
| 星期 | 周五 / 星期五 / 下周一 | 只往前找**最近的将来**那次；"下周"=下周一起算 |
| 月日 | 11月3日 / 3号 / 11-03 / 2026-11-03 | 不带年份按"今年；已过则明年" |
| 时刻 | 15:00 / 15点 / 下午3点 / 晚上八点半 / 中午 / 早上7点20 | 12 小时制按 上午/下午/晚上 校正；"中午"=12:00 |
| 重复 | 每天 8:00 / 每周一 10:00 / 每月1号 / 每 2 小时 | 生成 `recurrence`：`{kind: daily/weekly/monthly/every, at, dow/dom/seconds}` |

歧义处理（都写进测试）：
- "后天下午 3 点" → 优先"天"再挂"时刻"，两者都缺就报错并给出示例。
- 只给时刻且已过 → 顺延到明天（提醒"我按明天 X 点记的"）。
- 时区固定本机时区；夏令时不存在（中国无 DST），但**月份按本机日历**。
- 解析结果永远回显一遍（`"记下了：后天 15:00（2026-11-02）"`），让她和你都能当场纠错。

## 四、调度与"到点怎么办"

- 一条常驻线程，20 秒一跳；`next_at <= now` 就触发。线程只在 `serve_forever` 期间活，停用即停。
- **补发**：进程停过（电脑关机/模组停用）再起来，错过的点分两种处理——
  - 一次性提醒：迟了仍补一次，正文前加「（补）」；
  - 重复提醒：只补**最近一次**，不刷屏。
- 触发动作（顺序固定）：`notice.push`（保姆栏，带时间）→ 若 `chat=true` 且允许，再插一句短的 → `memory.note` 记一笔"我提醒了主人…"。
- **离线/忙碌时提醒【开/关】**（你给的设置之一）：
  - 开（默认）：到点照常提醒，保姆栏 + 聊天各一条。
  - 关：到点仍写保姆栏（不漏账），但**不在聊天里说**；等你回到 `online` 时补一次聊天提示。
  - 判断依据：`presence.read`（online / busy / away）。
- 重复提醒的"下一次"在触发后立刻算好（`next_at` 前滚），避免同一分钟内重复触发。
- 上限：待办 500 条、提醒 200 条、记事 2000 条；超了拒绝新增并提示先清理（防止 JSON 无限长）。

## 五、信息查询：把 web_bridge 并进来

旧 `web_bridge` 的实现（`server.py` 391 行）整体搬进来，保留它踩过的经验，不重写：

- `fetch(url, max_chars)`：只允许 http/https；解析到内网/回环/链路本地一律拒（防 SSRF）；3 MB 上限、15 s 超时；正则去 script/style/注释，块级标签转换行，`<title>` 与 meta description 单独取。
- `search(query, n, read_first)`：先 Bing（`www.bing.com/search`）再 DuckDuckGo（`html.duckduckgo.com`），解析 `b_algo` / `result__a`；去掉 utm_* 等跟踪参数去重；摘要全空时**自动读第一页**并挑与关键词最沾边的一条（省她反过来问你"读哪个"）。
- 证书：旧包带了一份 `cacert.pem`（235 KB）。新模组**默认用系统证书**，只有当用户机器证书链不全、报 SSL 错时，再在设置里开「使用模组自带 CA」（这次不随包带，减小体积）。

**网络查询功能强度【较弱搜索 / 普通搜索 / 全面搜索】**（你给的设置之一）——落成三组参数，模组内部统一读：

| 档 | 结果数 n | 自动读正文 | 单页字数 | 超时 | 适用 |
|---|---|---|---|---|---|
| 较弱搜索 | 3 | 不读 | — | 8 s | 只想知道"有没有这回事" |
| 普通搜索（默认） | 5 | 摘要全空才读 1 页 | 1,500 | 15 s | 日常问答 |
| 全面搜索 | 8 | 读最多 3 页，取最相关 | 4,000 | 25 s | "帮我查清楚"这类 |

**允许智能体自主上网【开/关】**（第三个设置）：
- 关：`rt_search` / `rt_fetch` 直接返回 `{ok:false, code:"web_off"}` + 一句"使用者把上网关了，先问他要不要查"。工具说明里也写清"可能被关"，她就不会反复试。
- 开（默认）：照上面强度执行。
- 注意：这不是"隐私模式"，只是权限；本地生活信息与常识问答本来就走同一套搜索，没有单独的离线知识库（真要离线得另配本地语料，那是另一个工程）。

「本地部署的网络查询功能」我的理解是：查询逻辑跑在本机（模组进程直连搜索引擎），不经过第三方 API、不经过 BAB 内核。如果你要的是"完全离线、不联网也能查"，那需要本地索引/知识包，工作量大一个量级，得单独立项——这点请在下一轮开始前告诉我。
